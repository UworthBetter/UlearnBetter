# ch09 日志美化与历史排查

> [!info] 视频位置
> [4:27 Pretty Logs](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=267s) · [4:51 Bisect](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=291s) · [5:14 Autosquash](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=314s)

## 🎯 本章目标
用图形化日志看清分支脉络，用 bisect 二分定位坏提交，再用交互式 rebase 把零碎提交压缩成一个干净的提交。

## 🌲 Pretty Logs：让 git log 可读

`git log` 是查看提交历史的常用命令，但问题在于：**项目越复杂，输出越难读**（[4:28](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=268s)）。解决方法是加三个选项：

```bash
git log --graph --oneline --decorate
```

| 选项 | 作用 |
| --- | --- |
| `--graph` | 画出提交图，能看出不同分支如何连接 |
| `--oneline` | 每个提交压缩成一行，输出更简洁 |
| `--decorate` | 显示分支/标签等引用装饰 |

这样就能得到更精炼的历史概览，直观看到分支之间的连接关系（[4:38](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=278s)）。

## 🔍 Bisect：二分查找坏提交

看日志时，里面很可能藏着某个**正在搞坏你应用的提交**。`git bisect` 通过二分搜索帮你定位它（[4:51](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=291s)）：

1. 从一个**已知有 bug 的提交**开始（通常是最新的提交——你刚发现应用坏了）。
2. 指定一个**最后已知正常的提交**（比如几小时前应用还能工作时的那个），让 bisect 在两者之间进行二分搜索。
3. Git 会依次切换到中间的提交，你检查后：
   - 提交正常 → 输入 `git bisect good`，继续往后找；
   - 提交有问题 → 输入 `git bisect bad`，往前收缩范围。
4. 最终锁定那个坏提交，**确切知道哪段代码需要修复**（[5:09](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=309s)）。

## 🍱 Autosquash：交互式 rebase 压缩提交

设想你在功能分支上有三个提交，准备合并进 main 分支（作者还顺带自嘲说漏口又改口成 main，[5:09](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=309s)）——但这些提交信息都没什么意义，最好压成一个提交。做法是在功能分支上运行交互式 rebase（[5:30](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=330s)）：

```bash
git rebase -i main
```

流程如下：

1. Git 弹出一个文件，列出该分支上的所有提交。
2. 在文件中给每个提交指定操作命令，保存并关闭：
   - `pick`：保留该提交；
   - `reword`：修改提交信息；
   - `squash`：把该提交合并进上一个提交。
3. Git 再弹出一个文件让你更新提交信息，默认是所有被压缩提交信息的组合。
4. 如果不想保留被合并提交的信息，用 `fixup` 代替 `squash`——它会直接丢弃那些信息（[5:51](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=351s)）。

### 提前埋点：fixup / squash 提交标志

更高效的做法：在分支上提交时就使用 `--fixup` 或 `--squash` 标志，**提前告诉 Git 你以后想把哪些提交压缩到一起**（[5:51](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=351s)）。之后执行 rebase 时加上 `--autosquash` 标志，Git 就能自动完成所有压缩，无需手动整理（[6:12](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=372s)）。

> [!quote] 视频要点
> "You'll find the bad one and know exactly which code needs to be fixed." —— bisect 结束时，你会确切知道该修哪段代码。
