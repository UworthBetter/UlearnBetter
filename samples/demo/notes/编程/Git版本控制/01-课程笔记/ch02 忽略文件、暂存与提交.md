# ch02 忽略文件、暂存与提交

> [!info] 视频位置
> [2:40 Git Ignore File](https://www.youtube.com/watch?v=HkdAHXoRtos&t=160s) · [3:24 Stage File](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s) · [4:08 Commit](https://www.youtube.com/watch?v=HkdAHXoRtos&t=248s)

## 🎯 本章目标
会用 `.gitignore` 过滤敏感与无关文件，掌握 `git add` 暂存的用法，并能写出清晰、描述性的提交信息。

## 一、创建 .gitignore：什么不该进版本控制

初始化仓库后（见 [[ch01 认识 Git 与初始化仓库]]），下一步是创建 `.gitignore` 文件——不是所有东西都该放进版本控制。作者点名了三类应该排除的内容（[2:41](https://www.youtube.com/watch?v=HkdAHXoRtos&t=160s)）：

| 应排除的内容 | 原因 |
| --- | --- |
| 敏感的私有 API 密钥 | 避免泄露到代码仓库 |
| 依赖的源代码（如 `node_modules`） | 可由依赖管理恢复，体积庞大 |
| 不必要的日志文件 | 与代码无关，频繁变动无意义 |

Git 会自动读取 `.gitignore`，过滤掉所有匹配其中文件路径或模式的内容。作者建议：手动创建当然可以，但更「专业」的方式是用 VS Code 插件，自动生成适配你开发环境的默认模板，省下不少时间（[3:03](https://www.youtube.com/watch?v=HkdAHXoRtos&t=183s)）。详见 [[忽略文件]]。

## 二、暂存文件：git add 与危险操作提醒

提交（[[提交 Commit]]）之前，第一步是把想包含进本次提交的文件暂存（加入 [[暂存区]]）：

1. 运行 `git add <文件>`，可以添加单个文件；
2. 也可以用 `git add .` 添加整个工作目录；
3. VS Code 用户可以直接点文件旁的 **加号/减号按钮** 来暂存或取消暂存；
4. 命令行下用 `git reset` 取消暂存。

> [!warning] 避坑：git reset --hard
> 作者特意提醒（[3:45](https://www.youtube.com/watch?v=HkdAHXoRtos&t=225s)）：`git reset` 带上 hard 标志（`--hard`）时，不仅会取消暂存，还会==把文件永久删除==——如果在一个新项目上运行它，所有文件都会被删掉，只能从头再来。

作者还给出一条他最重要的经验法则之一（[4:06](https://www.youtube.com/watch?v=HkdAHXoRtos&t=246s)）：==做很多小的提交（many small commits）==。这个习惯既能防止代码灾难性丢失，也让每次改动更容易追溯。

## 三、提交：git commit 与写好提交信息的流程

一切就绪后，完成第一次提交的完整流程如下（[4:08](https://www.youtube.com/watch?v=HkdAHXoRtos&t=248s)）：

1. **暂存**：运行 `git add`，把要提交的文件加入暂存区；
2. **提交**：运行 `git commit -m "信息"`，用 `-m` 标志附上一段描述性消息，说明这次改了什么；
3. **（可选）多行消息**：第一行写简要总结，第二行写更详细的改动说明；
4. **确认结果**：提交后文件会移出暂存区，得到干净的工作目录，且 Git 会明确列出本次提交中创建、修改或删除了哪些文件；
5. **回看历史**：在 GitLens 插件里可以看到代码改动的历史记录，能逐条浏览并精确查看哪些行发生了变化（[4:47](https://www.youtube.com/watch?v=HkdAHXoRtos&t=287s)）。

> [!quote] 作者的玩笑式建议
> 提交信息里用 emoji，「能让你的项目在 GitHub 上获得更多 star——因为 star 是衡量一个软件项目好坏的最佳方式」（[4:27](https://www.youtube.com/watch?v=HkdAHXoRtos&t=267s)）。😄（这是作者的调侃语气，以视频为准）
