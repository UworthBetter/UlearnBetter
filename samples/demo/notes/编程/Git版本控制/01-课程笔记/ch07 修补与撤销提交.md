# ch07 修补与撤销提交

> [!info] 视频位置
> [1:38 Amend](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=98s) · [2:03 Force Push](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=123s) · [2:24 Revert](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=144s)

## 🎯 本章目标
分清 amend、force push、revert 各自的适用场景与风险边界——修小错用 amend、已推送的错误改动用 revert，并能识别 force push 的危险。

## 修补最后一次提交（Amend）
出错了怎么办？提交信息打错字，不必 reset 再新建一个提交：加上 `--amend` 标志并写新消息，就能直接更新最新一次提交（[1:39](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=98s)）。

amend 还能补救漏提交的情况：
- **漏加文件**：把忘记 stage 的文件补上后用 `--amend`，即可把新文件并入上一次提交（[1:50 左右](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=98s)）
- **保留原提交信息**：只想补文件、不改消息时，再加 `--no-edit` 标志（[2:00](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=123s)）

> [!warning] 前提
> 作者提醒：amend "只在还没把代码推送到远程仓库时才真正有效"（[2:01](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=123s)）。一旦已推送，就需要下面两种手段。

## 三种手段对照（含 force push 的风险）
| 手段 | 适用场景 | 风险 |
| --- | --- | --- |
| `git commit --amend` | 修改最后一次提交的信息或内容（未推送时） | 已推送后远程与本地历史不一致 |
| `git push --force` | amend 后强行覆盖远程提交 | 若远程分支上有你没有的提交，它们会**永远丢失**，同事可能不高兴（[2:14](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=123s)） |
| `git revert` | 已推送的提交需要"撤销" | 几乎无风险：不改写历史 |

> [!quote] 视频原话
> "如果远程分支上有你没有的提交，你会永远失去它们，你的同事们可能不会太高兴。"（[2:14](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=123s)，以视频为准）

## 撤销已推送的提交（Revert）流程
把代码推到远程后发现它"完全是垃圾、根本不该存在"，怎么办（[2:30 左右](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=144s)）？

1. 确认要撤销的是哪一个提交。
2. 运行 `git revert <commit>`：它会让代码回到该提交之前的状态。
3. 注意 revert 的本质：它**不会**从历史中删除原提交，而是新增一个提交把内容退回原状（[2:38 左右](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=144s)）。
4. 结果：历史保持完整、可以安全推送——比"像创伤外科医生那样把东西拼回去"容易得多（[2:42](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=144s)）。

> [!quote] 视频原话
> "它有点像撤销，但不会把原提交从历史里移除，只是回到最初的状态。"（[2:38 左右](https://www.youtube.com/watch?v=ecK3EnyGD8o&t=144s)）
