# 🛠️ 新仓库上手清单

对应视频一《Git It? How to use Git and Github》ch01–ch02（[0:42 What is Git](https://www.youtube.com/watch?v=HkdAHXoRtos&t=42s) – [4:52](https://www.youtube.com/watch?v=HkdAHXoRtos&t=292s)）。

## 1️⃣ 初始化仓库
- [ ] 在项目目录运行 `git init`，把当前目录变成 Git 仓库（验证方式：终端输出 "Initialized empty Git repository"；VS Code 源代码管理面板出现变更列表）
- [ ] 确认项目里的文件显示为 **U（Untracked）** 图标，说明文件尚未被跟踪（验证方式：VS Code 源代码管理面板查看）
- [ ] 了解"反悔入口"：删除隐藏的 `.git` 目录即可完全取消 Git 初始化（验证方式：`ls -a` 能看到 `.git`；删除后源代码管理面板恢复 "No source control provider"）

## 2️⃣ 创建 .gitignore 挡住敏感文件
- [ ] 在仓库根目录创建 `.gitignore` 文件（验证方式：`ls` 可见该文件）
- [ ] 写入要排除的路径/模式：私密的 API 密钥、依赖目录（如 `node_modules`）、无用的日志文件（验证方式：被排除的文件不再出现在源代码管理变更列表中）
- [ ] （可选）用 VS Code 插件自动生成对应环境的默认忽略规则，省去手写（验证方式：生成的 `.gitignore` 包含常见条目）

## 3️⃣ 首次暂存与提交
- [ ] 运行 `git add .` 暂存整个工作目录，或 `git add <文件名>` 只暂存单个文件；也可在 VS Code 里点 **+** 号暂存（验证方式：`git status` 中文件进入 staged 状态）
- [ ] 运行 `git commit -m "描述本次改动的信息"` 完成首次提交；提交信息可写成多行——第一行摘要、第二行详细说明（验证方式：命令输出列出本次创建/修改/删除的文件，暂存区清空、工作目录干净）
- [ ] 记住撤销暂存用 `git reset`（不要加 `--hard`）（验证方式：`git status` 中文件回到 unstaged 状态）

## 4️⃣ 用 GitLens 回看历史
- [ ] 在 VS Code 中安装 GitLens 插件（验证方式：插件列表中显示已安装，编辑器内出现行内溯源信息）
- [ ] 打开 GitLens 面板浏览提交历史，逐条查看每次提交改了哪些行（验证方式：能看到刚做的首次提交及其变更详情）

> [!warning] 避坑
> - `git reset --hard` 会把未提交的改动**永久删除**，在新项目上误用等于从零重来——只用它时务必三思（视频原话提醒）。
> - `.git` 目录是仓库的全部历史，删除它 = 彻底放弃版本控制，删之前确认真的不要了。
> - 没写 `.gitignore` 就提交，容易把 API 密钥、`node_modules`、日志等一并入库，敏感信息一旦推上远端很难撤干净。
> - 养成"多而小的提交"习惯：提交越细粒度，出错时越容易定位和回退，合并冲突也好修（作者反复强调的核心实践）。
