# 📖 术语表

## 核心机制
| 术语 | 中文 | 一句话解释 | 笔记 |
| --- | --- | --- | --- |
| Commit | 提交 | 给整个项目拍一张带唯一 ID、不可篡改的快照，相当于代码历史书的一页。 | [[提交 Commit]] |
| Staging Area | 暂存区 | 用 git add 挑出这次要提交的改动，是工作区与提交之间的待办清单。 | [[暂存区]] |
| .gitignore | 忽略文件 | 声明哪些文件不进版本库，挡住密钥、node_modules 和日志。 | [[忽略文件]] |
| git init | 初始化仓库 | 在当前目录创建一个隐藏的 .git 目录，让 Git 开始追踪文件。 |  |

## 分支与合并
| 术语 | 中文 | 一句话解释 | 笔记 |
| --- | --- | --- | --- |
| Branch | 分支 | 从最新提交分出的平行开发路径，让多人多任务互不干扰。 | [[分支 Branch]] |
| Fast-forward | 快进合并 | 目标分支没有新提交时，合并只是把指针直接前移到特性分支的最新提交。 | [[快进合并]] |
| Merge Conflict | 合并冲突 | 两条分支改动了同一处代码，Git 无法自动裁决，需要人工选择保留哪边。 | [[合并冲突]] |
| Rebase / Squash | 变基与压缩 | 用交互式 rebase 的 squash 或 fixup 把零散提交整理压缩成一个干净的提交。 | [[变基与压缩]] |

## 撤销与修复
| 术语 | 中文 | 一句话解释 | 笔记 |
| --- | --- | --- | --- |
| git commit --amend | 修补提交 | 直接修改最近一次提交的信息或补交漏掉的文件，不必新建提交。 | [[修补提交 Amend]] |
| git revert | 撤销提交 | 生成一个反向提交把代码退回过去，原历史保留，是已推送提交上最安全的撤销方式。 | [[撤销提交 Revert]] |
| git reset --hard | 硬重置 | 用远程代码覆盖本地并丢弃所有未提交改动——慎用，本地修改会永久丢失。 |  |
| git clean | 清理未跟踪文件 | 删除 reset 之后残留的未跟踪文件和构建产物。 |  |

## 工作流提效
| 术语 | 中文 | 一句话解释 | 笔记 |
| --- | --- | --- | --- |
| git stash | 贮藏 | 把未完成的改动临时收起而不提交，之后用 pop 或 apply 取回继续干活。 | [[贮藏 Stash]] |
| git bisect | 二分排查 | 在已知好与坏的两个提交之间做二分搜索，快速定位引入 bug 的那一笔。 | [[二分排查 Bisect]] |
| Alias | 命令别名 | 用 git config 给常用命令起短名（如 ac = add + commit），加快操作速度。 |  |
| Git Hooks | 钩子 | 在提交等事件发生前后自动运行脚本（可用 husky 简化配置），用于校验代码质量。 |  |
| Pull Request | 拉取请求 | 开源协作的标准流程：fork → clone → 建分支 → 改代码 → 请求合并进原仓库。 |  |
| Fork | 复刻仓库 | 把别人的仓库复制一份到自己账号下，再 clone 到本地进行修改。 |  |
| Codespaces / 按句号键 | 云端开发 | 在 GitHub 上按句号键即可打开浏览器版 VS Code，或建 Codespace 获得完整终端能力。 |  |
