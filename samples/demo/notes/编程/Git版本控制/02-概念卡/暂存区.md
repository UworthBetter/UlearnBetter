# 暂存区

> [!abstract] 一句话定义
> ==用 git add 挑出这次要提交的改动，是工作区与提交之间的待办清单。==

## 📌 是什么

- 提交（commit）不是直接打包整个工作目录，而是先「staging（暂存）」——把想要纳入这次提交的文件挑出来（作者原话："the first thing we want to do is stage the files that we want included in this commit"）[3:24](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s)。
- 命令是 `git add`：可以添加单个文件，也可以用 `.`（句点）把整个工作目录的改动全部暂存 [3:24](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s)。
- VS Code 让暂存变得可视化：点加号按钮暂存（stage）、点减号取消暂存（unstage），不用敲命令 [3:24](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s)。
- 从暂存区撤回文件用 `git reset`，但要小心 `--hard` 标志——它不仅取消暂存，还会把文件永久删除、无法恢复（作者强调"be careful with this one"）[3:24](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s)。
- 暂存 → 提交是一套固定流程：先 `git add` 暂存，再 `git commit -m` 写描述信息提交；提交后暂存区清空，得到干净的工作目录 [4:06](https://www.youtube.com/watch?v=HkdAHXoRtos&t=246s)。

## 🧩 在视频/系统中的角色

出现在 ch02 忽略文件、暂存与提交（约 [3:24](https://www.youtube.com/watch?v=HkdAHXoRtos&t=204s) 起）。在视频的 Git 基础工作流中，暂存区是连接「改动文件」与「提交快照」的中间环节：先过滤决定哪些改动进入本次快照，再由 [[提交 Commit]] 落入历史。它也是后续所有提交流程（快速提交、修补提交等）的第一步。

## 📌 执行顺序

1. 修改文件后，用 `git add <文件>`（或 `git add .`）暂存要提交的改动。
2. 也可以在 VS Code 中点击文件旁的加号按钮完成暂存。
3. 若挑错了，用 `git reset` 取消暂存（切勿随意加 `--hard`）。
4. 运行 `git commit -m "<描述信息>"` 提交。
5. 提交完成后暂存区被清空，工作目录恢复干净，Git 会列出本次创建/修改/删除的文件。

## ⚖️ 优点与局限

| ✅ 优点 | ⚠️ 局限 |
| --- | --- |
| 可以精确挑选这次提交包含哪些改动，不必一次打包整个目录（以视频为准） | `git reset --hard` 一旦误用会永久删除文件、无法恢复，风险很高（视频明确警告） |
| VS Code 提供加减号按钮，暂存/取消暂存非常直观，降低命令行门槛 | 新手容易把「暂存」「提交」两个步骤混淆，流程比直觉多一步 |
