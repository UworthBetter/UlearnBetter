# 分支 Branch

> [!abstract] 一句话定义
> ==从最新提交分出的平行开发路径，让多人多任务互不干扰。==

## 📌 是什么

- master（主分支）就像树的主干，存放要发布给客户的实际源码，此前所有工作都默认在它上面进行（[4:53](https://www.youtube.com/watch?v=HkdAHXoRtos&t=293s)）
- 当代码库已稳定、又需要修 bug 或试验新特性时，典型的做法是：基于最近一次提交创建一个新分支，在上面修复，完成后合并回 master（[4:53](https://www.youtube.com/watch?v=HkdAHXoRtos&t=293s)）
- 这样多个开发者可以各自在自己的分支上开发同一个代码库，而不会互相踩脚（[5:14](https://www.youtube.com/watch?v=HkdAHXoRtos&t=314s)）
- 用 `git branch` 可以查看当前代码库里的所有分支；用 `checkout` 命令可以在分支之间切换；分支尚未创建时，用 `-b` 标志可以在切换的同时创建它（视频示例中命名为 `feature`）（[5:14](https://www.youtube.com/watch?v=HkdAHXoRtos&t=314s)）
- 在新分支上写的代码会被隔离在该分支内；切回 master 时，分支上未合并的新文件会“消失”，回到 master 的原始状态（[5:55](https://www.youtube.com/watch?v=HkdAHXoRtos&t=355s)）

## 📌 执行顺序

1. 用 `git branch` 查看现有分支（初始通常只有 master）
2. 用 `checkout -b <分支名>`（如 `feature`）创建并切换到新分支
3. 在新分支上写代码，改动会隔离在该分支内
4. 提交（commit）改动到该分支（视频里是在 VS Code 中直接提交）
5. 用 `checkout` 切回 master，工作区回到原始状态
6. 分支就绪后，再合并回 master（详见 [[快进合并]]）

## 🧩 在视频/系统中的角色

分支出现在 **ch03 分支与快进合并**，是 Git 并行开发的核心机制：它在“提交 Commit 构成的历史主干”之上提供了隔离层，让修 bug、试验新特性与稳定的主干互不干扰；它与 [[快进合并]]、[[合并冲突]] 一起构成本视频“分支与合并”这一组主题，也是后续 [[贮藏 Stash]]（切分支前临时收起未完成改动）等技巧的使用场景。

## ⚖️ 优点与局限

| ✅ 优点 | ⚠️ 局限 |
| --- | --- |
| 多人可同时在各自分支上开发同一代码库，互不踩脚 | 两条分支改到同一处代码时会产生 [[合并冲突]]，需人工裁决 |
| 新特性/修 bug 的代码被隔离在分支内，稳定主干不受影响 | 切换分支前若有未完成的改动，需提交或用 `git stash` 收起 |
| 完成后可合并回 master，历史清晰、随时可切回原始状态 | 以视频为准 |
