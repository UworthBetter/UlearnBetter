# 忽略文件

> [!abstract] 一句话定义
> ==通过 `.gitignore` 声明哪些文件不进版本库，挡住密钥、node_modules 和日志等不该被追踪的内容。==

## 📌 是什么

- 新建 GitHub 仓库时的「下一个重要步骤」就是创建 git ignore 文件，因为并非所有文件都适合放进版本控制 [2:41](https://www.youtube.com/watch?v=HkdAHXoRtos&t=161s)
- 必须挡在仓库外的典型内容：敏感的私有 API 密钥（密钥一旦提交就等于公开）、依赖的源码如 `node_modules`、以及不必要的日志文件 [2:41](https://www.youtube.com/watch?v=HkdAHXoRtos&t=161s)
- Git 会自动读取 `.gitignore`，把匹配其中文件路径或模式的文件过滤掉，不纳入版本库 [2:41](https://www.youtube.com/watch?v=HkdAHXoRtos&t=161s)
- 可以手动创建该文件，但视频推荐的「专业做法」是用 VS Code 插件自动生成适配你开发环境的默认规则，省去大量时间 [3:03](https://www.youtube.com/watch?v=HkdAHXoRtos&t=183s)

## 🧩 在视频/系统中的角色

出现在 **ch02 忽略文件、暂存与提交**：它是仓库初始化之后、第一次提交之前的准备工作。没有它，`git add .` 会把密钥和依赖一股脑塞进暂存区再提交；有了它，Git 在暂存与提交之前就先把垃圾和危险文件过滤掉，是整个「初始化 → 暂存 → 提交」流程的安全闸门。

## 📌 执行顺序

1. 初始化仓库后，准备首次提交前，先创建 `.gitignore` 文件
2. 手写或（推荐）用 VS Code 插件自动生成适配当前环境的默认忽略规则
3. 在文件中声明要排除的路径或模式：API 密钥文件、`node_modules`、日志文件等
4. 之后正常执行 `git add` 暂存——Git 会自动过滤掉所有被匹配的文件
5. 提交后，被忽略的文件将不出现在版本历史中

## ⚖️ 优点与局限

| ✅ 优点 | ⚠️ 局限 |
| --- | --- |
| 自动过滤敏感内容（API 密钥），避免密钥泄露到 GitHub | 规则写漏了照样会被提交，不能只靠插件生成的默认配置（以视频为准） |
| 排除 `node_modules`、日志等无关文件，保持仓库干净、提交历史清晰 | 视频未提及已提交文件的取消忽略方法，细节以视频为准 |
| 用 VS Code 插件一键生成环境默认规则，省时省力 | 手动编写规则需要了解路径/模式语法，有学习成本（以视频为准） |
