# 学习 Agent 产品蓝图

**多领域个性化学习陪伴系统**

文档版本：v1.1 | 基于产品讨论整理 | 日期：2026年11月

---

## 1. 产品愿景

打造一个功能丰富、深度懂用户、可高度个性化、具有陪伴感的通用学习 Agent。

它不是单一课程或考证工具，而是能够同时管理多条学习线（大学课业、金融量化、AI 前沿产品/技术/应用等）的私人学习管家。Agent 主动帮助用户整理学习任务、量身打造学习路径、加工内容（视频、课件等）、建立知识关联，并将所有产出沉淀为长期个人知识资产。

核心目标：让用户感觉「它真的懂我」，从而产生使用依赖，并为后续付费奠定基础。

## 2. 核心问题与价值主张

### 当前痛点

- 视频/材料转笔记后，仍停留在被动记录，距离真正学习（主动加工、记忆、应用）仍有距离
- 学习需求多线并行，缺乏统一的任务整理与个性化规划
- 现有工具（笔记软件、闪卡、课程平台）割裂，难以形成闭环与长期资产
- 缺乏低摩擦的陪伴入口，坚持成本高

### 核心价值

- 深度用户理解：记住偏好、进度、薄弱点、学习节奏，越用越精准
- 主动任务规划：拆解目标、生成可执行任务、动态调整
- 内容加工闭环：视频/资料 → 笔记 + 导图 + 问答卡片 + 复习
- 知识关联与主动发现：跨来源连接概念，推荐相关内容
- 陪伴与习惯形成：桌宠/应用入口降低心理门槛，形成日常使用习惯

## 3. 产品架构

三层架构，加一条贯穿原则：

| 层级 | 职责与形态 |
|------|------------|
| **陪伴入口层** | 桌宠（可定制形象/性格，壳只做渲染与路由）、控制台/独立应用、系统通知。低摩擦入口与情感连接。 |
| **学习 Agent 核心** | 内容加工（视频/PDF）、复习与掌握度（FSRS）、任务规划、跨来源关联与发现、用户上下文。 |
| **知识资产层** | Obsidian Vault 为唯一事实源（Markdown、闪卡、导图、图谱、复习记录）。 |

**贯穿原则：vault 是唯一事实源，文件即 API。** 所有入口（桌宠、控制台、Agent）只通过约定的文件读写通信，不在 vault 之外另建数据库，避免双源失真。

### 3.1 数据契约（入口层 ⇄ Agent 层的接口）

| 文件 | 用途 | 读写方 |
|------|------|--------|
| `_Inbox/收集箱.md` | 收集池：链接 / 标题 / 状态（待评估·待深学·已入库·跳过）/ 评估结论 | 桌宠、控制台写，Agent 读写 |
| `_Inbox/今日队列.md` | 每日刷新：今日到期卡数、建议深学条目、打卡与专注统计 | Agent 生成，桌宠只读（驱动表情与话术） |
| `<主题>/02-概念卡/*.md` frontmatter | 复习状态：`next-review` `stability` `difficulty` `reps` `lapses` | 桌宠复习时写（FSRS），Agent 生成时初始化 |
| `90-资源/graph.json`、`全局图谱.json` | 概念图谱 | Agent 生成，控制台/桌宠只读 |
| `_系统/用户画像.md` | 偏好、目标、时间可用性、薄弱点、长期记忆摘要 | Agent 维护，L1 对话时注入 |

### 3.2 执行分层路由（入口层怎么选执行通道）

| 层级 | 场景 | 通道 | 延迟 |
|------|------|------|------|
| **L0 纯本地** | 表情状态、番茄钟、统计；**翻卡复习**（读到期卡 → 评分 → py-fsrs 排期 → 写回） | 本地文件 + 算法库，无 LLM | 0 |
| **L1 单次 LLM** | 陪聊、鼓励、快问快答、单篇摘要、晨间问候 | 直连 LLM API，注入画像 + 今日队列 | 1–3 秒 |
| **L2 全 Agent** | 视频→笔记、快速评估（真抓字幕）、全局图谱、周计划、跨库整理 | ZCode（技能 + webReader + MCP 工具） | 10 秒+ |

桌宠约 90% 的时间在 L0/L1 自转，只有重加工才路由到 ZCode。这是陪伴感（秒级响应）与能力（全工具链）兼得的关键。

## 4. 关键功能模块

### 4.1 用户深度理解与个性化

vault 本身就是长期记忆：复习历史、打卡、批注天然留在 markdown 里，Agent 开工即读即懂。画像显式化为 `_系统/用户画像.md`，由 Agent 随复习与交互自动更新；支持隐式行为推断，但 v1 不引入向量库、不另建画像数据库。

### 4.2 任务规划引擎

多主题并行 = vault 主题树（课业 / 量化 / AI 各一棵）+ 全局图谱。规划 = 规则 + 判断：收集箱积压 → 每周挑 N 个 → 每日「1 个深学 + Y 张到期卡」；动态调整由 Agent 在每日队列刷新时完成。不引入通用规划框架。

### 4.3 内容加工与可视化

- 视频链接 → 结构化笔记 + 带时间戳跳转 + 概念图谱 + 主动回忆问答（现有 youtube-obsidian-notes 技能升级）
- 关键帧提取（yt-dlp + ffmpeg 按时间戳抽帧）：可行但暂缓，优先级低于复习闭环
- PDF / 课件 / 录音：同一条流水线的输入源扩展
- 可视化输出：Mermaid / Obsidian Canvas / graph.json（对话内交互图谱）

### 4.4 复习与掌握度闭环

- 闪卡自动生成（概念卡 → 问答 + 填空），FSRS 调度（py-fsrs，四档评分 Again/Hard/Good/Easy；桌宠两键「忘了/记得」映射 Again/Good）
- 复习状态写进概念卡 frontmatter（见数据契约）
- **单一调度原则**：FSRS 归本系统，Obsidian Spaced Repetition 插件不对同批卡片排期；Obsidian 内只用 Dataview 做只读展示（今日到期几张），避免双调度打架
- 掌握度可视化、周报

### 4.5 陪伴入口（桌宠）

- **壳薄原则**：桌宠壳不跑 LLM、不装业务逻辑——读状态文件渲染表情与话术，交互经 3.2 路由分发
- **人格在 Agent 侧**：话术由 Agent 生成写入状态文件；换形象 = 换一份 SVG/动画帧
- 核心动作：到点提醒、快速收集（贴链接 → L2 评估）、一键开始复习（L0）、陪学番茄钟（L0）、轻对话（L1）
- 复杂操作跳转控制台 / Obsidian

## 5. 技术与生态站位

明确站在前人肩膀上，避免重复造轮子：

| 能力 | 推荐方案 |
|------|----------|
| **知识库底座** | Obsidian，Markdown 直读直写（文件即 API）。Local REST API 插件降级为后续选项——仅在需要让 Obsidian 执行动作（跳转、打开笔记）时启用 |
| **间隔重复** | FSRS 开源算法（py-fsrs / ts-fsrs / fsrs-rs），不自研 |
| **可视化** | Excalidraw、Markmap、Obsidian Canvas、Mermaid；图谱数据统一 graph.json |
| **桌宠壳** | 自写 PyQt6 透明置顶窗（几百行）；可参考 **Shimeji-ee**（XML 动画剧本、换皮最容易）与 **VPet**（国产虚拟桌宠、插件生态）。注：早期版本引用的 NekoAI / OpenPet / Petsona 等项目未能核实，勿直接依赖 |
| **Agent 执行** | ZCode（视频流水线、字幕真伪校验、断链校验、MCP 工具已沉淀为技能）；L1 轻对话走轻量 LLM API |

## 6. 用户粘性策略

1. **资产粘性**：笔记、卡片、导图、复习记录、个人知识图谱持续积累，形成高沉没成本。
2. **习惯粘性**：间隔重复提醒 + 每日轻量任务 + Streak，形成「今天不打开就有点亏」的感觉。
3. **情感粘性**：桌宠陪伴、个性化记忆、轻微人格，降低打开门槛。
4. **效果粘性**：用户能明显感知「不用这个就会忘」，理性依赖。依赖 4.4 复习闭环真正落地，故最优先建设。
5. **兼容粘性**：深度兼容 Obsidian（只读展示不锁定），降低切换阻力，成为增强而非替代。

## 7. 演进路径

### 阶段一：闭环引擎（当前）

数据契约定稿 → 技能升级：收集箱 + 快速评估、FSRS 复习引擎、全局图谱。**完成即在 ZCode 对话内跑通完整闭环：收集 → 深学 → 翻卡复习 → 排期。** 此时已拥有可用的个人学习系统，入口是对话。

### 阶段二：入口换壳

桌宠真壳（PyQt6，承载 L0 + L1，L2 路由到 ZCode）+ 控制台接真实 vault 数据。入口从「对话」换成「人格化常驻」，引擎不变，壳是轻投入。

### 阶段三：习惯层

定时任务：早晨刷新今日队列、晚间汇总学习时长；系统通知；Streak。目标是不打开任何东西也知道今天该学什么。

### 阶段四：独立应用与生态（按需启动）

Tauri 独立应用（任务看板、进度可视化）、浏览器插件（直接丢链接）、移动端轻查看、语义检索。均为体验扩展，不阻塞前三阶段。

## 8. 最小可验证版本（MVP）

优先验证「好用 + 愿意持续使用」：

- 视频 → 结构化笔记 + 时间戳跳转 + 问答卡片 【已具备，升级即可】
- FSRS 闪卡复习闭环（含单一调度规避） 【阶段一新建，最优先】
- 收集箱 + 快速评估 【阶段一新建】
- 多主题学习空间（课业/量化/AI 并行） 【免费获得：vault 主题目录 + 全局图谱】
- 基础用户上下文（画像文件 + 今日队列，无向量库） 【阶段一新建】
- 每日提醒与 Streak 【阶段三，桌宠/通知承载】
- 关键帧提取 【暂缓，排在复习闭环之后】

## 附：v1.0 → v1.1 修订记录

1. **Local REST API 降级为后续选项，改为「文件即 API」+ 数据契约（§3.1）**——去掉 Obsidian 常驻依赖，vault 成为唯一事实源，三个入口通过约定文件通信。
2. **新增执行分层路由 L0/L1/L2（§3.2）**——翻卡复习是本地文件 + 算法库操作，根本不需要 LLM；轻对话走单次 API（1–3 秒）；重加工才路由 ZCode。这是陪伴感与能力兼得的架构决定。
3. **用户记忆改为「vault 即记忆」+ 画像文件（§4.1）**——删除 v1.0「自建知识库作为补充」的双源表述，画像显式化为 `_系统/用户画像.md`。
4. **复习模块新增「单一调度原则」（§4.4）**——FSRS 归本系统，Obsidian Spaced Repetition 插件不对同批卡片排期，防止双调度打架。
5. **桌宠参考项目替换为可验证项（Shimeji-ee / VPet）**，并明确「壳不跑 LLM、人格在 Agent 侧」（§4.5、§5）；v1.0 引用的 NekoAI / OpenPet / Petsona 等未能核实，已标注勿依赖。
6. **演进路径重排**——独立应用从阶段二移至阶段四，桌宠提前到阶段二；理由：桌宠是几百行的薄壳（轻投入），独立应用是重投入，且阶段一完成后系统已完整可用，换壳只是换入口。MVP 清单补充「已具备 / 待建 / 暂缓」标注。
